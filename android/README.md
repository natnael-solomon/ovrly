# Android

Kotlin/Jetpack Compose app for Android 10+ (API 29), with floating controls, local capture and share validation. No backend or research processing is connected.

## Setup

Install JDK 21, Android SDK platform 37, Build Tools 36.0.0 and Platform Tools, and accept the SDK licenses. The build uses Gradle 9.8.0 (wrapper) and Android Gradle plugin 9.4.1 with its built-in Kotlin; lint runs with warnings as errors.

Open this directory in Android Studio and select JDK 21 for Gradle. For terminal builds, set `JAVA_HOME` and `ANDROID_HOME`; any `local.properties` must point to the same SDK and stay uncommitted.

From the repository root, build the debug APK, run unit tests and lint:

### Windows

```powershell
.\scripts\android.ps1 -JdkPath $env:JAVA_HOME -SdkPath $env:ANDROID_HOME
```

### Linux / WSL

```bash
cd android
sh gradlew --no-daemon --console=plain :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

Use a Linux JDK and SDK in WSL, with the checkout and Gradle caches in the Linux filesystem.

APK: `app/build/outputs/apk/debug/app-debug.apk` (relative to this directory). No backend or provider credentials are required.

Keep personal files in `.local`, experiments in `.scratch` and APK exports in `exports` at the repository root; these directories are Git-ignored.

## Design gallery

Open `app/src/main/java/app/ovrly/ui/GalleryPreviews.kt` in Studio's Design or Split view. Gallery selections do not change the live overlay; `GlassOverlay.kt` contains the live-control previews.

## App icon

The launcher icon is an adaptive icon (`mipmap-anydpi/ic_launcher.xml`): the rendered chrome ring as the foreground (`mipmap-*/ic_launcher_foreground.webp`, 108 dp canvas at five densities, ring at 92% of the 66 dp safe zone), a navy radial gradient with a faint lavender bloom as the background (`drawable/ic_launcher_background.xml`), and the thin two-gap ring as the monochrome layer for Android 13+ themed icons (`drawable/ic_launcher_monochrome.xml`). `scripts/splash_icon.py` regenerates the foreground bitmaps together with the splash asset. Notifications and the compact overlay control keep the monochrome `drawable/ic_ovrly.xml`.

## Header wordmark

The Your space and Explore headers show a rendered chrome `ovrly` wordmark (`drawable-*/wordmark_ovrly.webp`, 40 dp tall at five densities, generated by `scripts/splash_icon.py --wordmark`) instead of text. A soft diagonal glare sweeps across the letterforms every ~5 s (`Modifier.chromeGlare`); it is masked to the bitmap's own pixels, animates in the draw phase without recomposition, pauses off screen and follows the system animator scale. In Light mode the chrome sits close in value to paper, so three layers are drawn beneath it: a blurred ink drop-shadow, a blurred sheen halo and a crisp ink edge. Dark mode needs none of these and uses a stronger glare instead.

## Launch splash

Cold and warm launches use Android's native SplashScreen API through AndroidX Core SplashScreen, including its Android 10/11 compatibility resources. The static launch artwork is a large rendered chrome two-gap ring on Chrome black (`#080910`). It is a local bitmap, not a loading screen or a separate Activity: there is no timer, spinner, network request or keep-on-screen condition. Once the app has drawn its first frame, the splash hands off over about 900 ms: the ring lifts to 1.3× and fades while the splash surface dissolves, and underneath, on the same clock, the app content fades in and rises 24 dp into place (Material emphasized-decelerate easing). Durations follow the system animator scale, so reduced motion collapses the handoff to an instant swap; recreated Activities (rotation, restore) skip it, and a 2.5 s safety timeout reveals content if the platform never reports a splash exit. Hot resumes do not replay an intro. This branding does not make startup faster.

On Android 12+ the splash background follows the saved appearance: choosing Light registers `Theme.Ovrly.Starting.Light` with the system (`SplashScreen.setSplashScreenTheme`), so the next cold start opens on paper (`#F0EFE5`) with light system bars; choosing Dark clears the override back to the manifest theme. Android 10/11 have no such hook and always show the Chrome-black compat splash before a saved Light first frame.

Android 12+ owns the icon mask and placement: a plain drawable is inset to the centered 192 dp circle of the 288 dp canvas and masked, so that circle is the hard size limit for any splash artwork. The asset is `drawable-*/splash_ovrly.webp`, a 288 dp canvas at every density (lossy WebP with an exact alpha channel, 15–79 KB each), with the ring filling 97% of the mask circle. The `ovrly` wordmark is deliberately not part of the splash: stacking it under the ring inside the same circle roughly halves the ring, and the name appears in the app header on the first frame anyway. The notification icon (`ic_ovrly.xml`) is unchanged.

Regenerate the assets from rendered PNGs with transparent backgrounds using `python scripts/splash_icon.py <ring.png> --wordmark <wordmark.png>` (needs Pillow and numpy; not part of the Gradle build or CI). The script removes red anti-aliasing fringe from the source renders, centres the ring inside the mask circle, writes the splash, launcher foreground and header wordmark at every density, and refuses to write a splash that would be clipped, look small or carry a colour fringe. `LaunchSplashResourcesTest` checks the shipped files' canvases, alpha flags, sizes and wiring.

Launch branding ignores the system dark-mode setting and follows only the app's own saved appearance. `MainActivity` installs the splash, loads the saved appearance, registers the matching splash theme and applies the app theme, all before `super.onCreate`. Existing restored state and incoming-intent routing are unchanged.

**Known limitation:** on Android 12 the platform draws the splash icon only when the launch comes from the home process, SystemUI or the system uid. On a Samsung SM-A217F (Android 12) the same APK shows the ring from Samsung's One UI Home but only the black background from Niagara Launcher, and `adb shell am start` launches never show it. Android 13+ honours the app's `icon_preferred` request; an Android 15 emulator shows the ring from every launch source. There is no supported per-app override for this on Android 12.

## Appearance and overlay demo

Liquid Chrome is the fresh-install default; existing Light/Dark choices are preserved independently of Android's theme. Light mode follows Mock 1. Both apply to all screens, dialogs, overlays and the gallery. Lexend is bundled for interface text; Instrument Serif is retained for the wordmark and sample titles. Both retain their [SIL Open Font licenses](app/src/main/assets/licenses/).

The app opens on **Your space**, a clearly labeled sample collection. **Explore** offers topic filters, search and sample reports with original chrome artwork. Sample saves affect the preview collection only and survive navigation and restored activity state, not a fresh session. No account, saved research or backend is implied. **Settings** retains capture, permissions, overlay controls, appearance, share intake, voice, storage and gallery access, with technical details behind disclosures. Overlay setup, notifications and incoming shares route directly to Settings.

The larger overlay demo is explicitly enabled from Settings or the gallery and requires display-over-other-apps permission. All claims and evidence are labeled samples. If capture or voice is running, confirmation is required to stop it first. The demo replaces the compact controls, never records or contacts a provider, and has a close button and notification action. Closing it never restarts a session. It opens in the bottom half of the usable screen, spans its width with 16 dp side/bottom margins, and stays below half-height. Drag its header vertically to reposition it; scroll its body independently. System bars and cutouts remain outside the panel.

The service now hosts a public Android `Window` for localized background blur on supported Android 12+ devices. Unsupported devices, runtime blur disablement and the higher-opacity preference use solid, readable theme surfaces. No screen capture, hidden API or whole-screen blur is used for this effect. Native blur remains a device-validation requirement, not a guarantee for every phone. See [architecture](../docs/architecture.md#overlay-material-and-demo-boundaries) for the validation boundary.

## Optional voice experiment

Voxide is disabled by default; native authorization and compatibility remain unresolved. After provider approval, configure `voxide.local.properties` from the example file using only a publishable key, never a secret key: values are embedded in the APK.

Starting voice sends microphone audio to Voxide for gallery navigation only. It stops when the companion leaves the foreground or capture starts.
